# Source Editor

SideStore용 소스 JSON을 만들고 관리하는 SwiftUI iOS 앱입니다. JSON 저장 시 소스 변환 규칙에 맞춰 출력합니다.

`public`은 공유용 브랜치입니다. 다운로드 URL을 입력한 그대로 JSON 미리보기·파일 저장·GitHub 업로드에 사용하며, 특정 Cloudflare Workers 프록시로 자동 변환하지 않습니다. 개인용 `main` 브랜치와 다운로드 URL 처리 및 GitHub 업로드 초기값이 다릅니다.

## 기능

- 소스 탭의 웹사이트는 선택 사항이며, 입력하면 JSON의 `website`에 포함하고 비워 두면 생략합니다.

- 사진과 같은 순서로 소스 이미지, 색상, 이름, 설명, 링크, 추천 앱 편집
- 소스 헤더·소스 아이콘·앱 아이콘·iPhone/iPad 스크린샷·뉴스 포스터에서 사진·파일 선택 → 위치·크기 조정 → Cloudinary 업로드 지원. 적용 후 공개 이미지 URL이 JSON에 저장됩니다.
- 헤더·뉴스는 5:3, 소스·앱 아이콘은 1:1 자르기 프레임을 사용합니다. 사진 드래그·두 손가락 확대·축소와 프레임 이동·크기 조절 후 선택 영역만 업로드합니다.
- 소스·뉴스의 **소스코드 보기**는 파일 탭의 JSON 미리보기에서 해당 소스 정보·뉴스 코드로 이동하고 잠시 강조합니다. 앱 탭에서는 **소스코드 보기 → 앱 선택**으로 해당 앱 코드로 이동합니다.
- 앱과 버전, iPhone/iPad 스크린샷, 권한 편집
- 앱 탭에서 아이콘·틴트 색상이 보이는 카드 목록을 검색하고 앱별 편집 화면에서 스크린샷, 버전, 개인정보 권한, Entitlements를 관리
- 앱 카드는 길게 눌러 순서를 바꾸고, 편집 모드의 3줄 손잡이는 누른 채 바로 드래그해 순서를 변경. 소스 탭에서 선택한 대표 앱의 손잡이도 바로 드래그 가능
- 앱 편집 화면에서 IPA/ADP 파일을 고르면 앱 이름, 번들 ID, 버전, 빌드 번호, 최소 iOS 버전, 파일 크기와 아이콘을 자동으로 읽습니다. 아이콘을 추출하면 조정 화면이나 추가 버튼 없이 즉시 Cloudinary에 PNG로 공개 업로드하고 아이콘 URL을 자동 입력합니다. 배포용 다운로드 URL은 직접 입력해야 합니다.
- 뉴스 항목 편집
- 기존 Source JSON 불러오기, 실시간 JSON 미리보기, 파일로 저장
- JSON 미리보기의 **전체 복사** 버튼과 길게 눌러 부분 선택·**복사하기** 메뉴 지원. 앱 코드는 이름·식별자를 먼저, `privacy`를 포함한 `appPermissions`를 마지막에 출력
- JSON 파일 선택 시 `.json` 형식만 허용하고, 가져오는 동안 읽은 파일 양에 따른 0~100% 진행 막대 표시
- 필수 입력 항목과 중복 식별자 확인
- 작업 내용 기기 내 자동 저장
- iPad의 넓은 화면에서는 사이드바와 편집 화면을 나란히 표시하고, 좁은 창에서는 탭 화면으로 전환
- 이미 선택된 하단 탭 또는 넓은 iPad 사이드바의 현재 메뉴를 다시 누르면 해당 기본 화면 맨 위로 스크롤. 세로·가로 전환 시 선택 메뉴 유지
- 앱을 열면 시작 화면에서 새 프로젝트, 이전 작업 계속하기 또는 기존 JSON 불러오기를 선택
- 입력 화면에서 키보드 위의 **키보드 내리기** 버튼으로 입력 종료
- JSON 저장 시 버전 최신순 정렬, 날짜 `+09:00` 형식, 누락된 최소 iOS 버전 `16.1` 보정. 다운로드 URL은 입력한 주소 그대로 유지
- 파일 탭에서 현재 JSON을 원하는 GitHub 저장소의 브랜치와 JSON 파일 경로에 업로드. 개인용 GitHub 토큰은 저장소별로 기기 키체인에 저장
- GitHub 업로드 중 전송량에 따른 0~100% 진행 막대를 표시하고 완료되면 팝업으로 결과 안내

## 사용법

1. **소스** 탭에서 이름을 입력합니다.
2. **앱** 탭에서 앱과 최소 하나의 버전을 추가합니다. 다운로드 URL은 게시된 IPA 또는 ADP 파일을 가리켜야 합니다. 크기는 바이트 단위입니다.
3. 필요하면 **뉴스**를 추가합니다.
4. **파일** 탭에서 Actions 아래의 검사 결과와 JSON 미리보기를 확인하고 **JSON 내보내기**를 누릅니다. 기존 JSON은 같은 탭의 **JSON 불러오기**에서 열 수 있고, **GitHub에 업로드하기**에서 바로 업로드 화면을 열 수 있습니다.
5. 저장소에 직접 반영하려면 **파일 → GitHub에 업로드하기**에서 저장소(`소유자/저장소` 또는 GitHub URL), 브랜치, JSON 파일 경로를 입력합니다. 저장소는 직접 입력해야 하며, 브랜치와 파일 경로의 초기값은 `main`, `Source.json`입니다. 공개·비공개 저장소별 사용법은 아래를 참고하세요. 앱에서 직접 업로드할 때는 두 유형 모두 쓰기 권한 토큰이 필요하며, 토큰은 저장소별로 기기 키체인에 저장됩니다.

이 앱은 JSON 파일을 생성하고 선택한 공개·비공개 GitHub 저장소에 업로드할 수 있습니다. 실제 IPA/ADP 파일은 사용자가 별도로 호스팅해야 SideStore 소스로 배포할 수 있습니다. GitHub 토큰은 각 사용자가 자신의 기기에서 설정합니다. 뉴스 포스터는 별도 가입이나 키 입력 없이 Cloudinary에 업로드합니다. 같은 앱 식별자로 기존 설치본을 업데이트하면 기기에 저장된 이전 GitHub 업로드 설정은 유지될 수 있습니다.

### JSON 불러오기

파일 탭의 **JSON 불러오기**에서 다음 중 하나를 선택합니다.

- **파일 앱에서 불러오기**: 기기의 `.json` 파일을 선택합니다.
- **공개 저장소에서 불러오기**: GitHub JSON 파일의 Raw 주소 또는 파일 보기 주소를 입력합니다.
- **비공개 저장소에서 불러오기**: 파일 주소와 저장소 읽기 권한 토큰을 입력합니다. 토큰 입력란 아래의 작은 파란색 **토큰 만드는 방법** 링크로 앱 내 가이드를 열 수 있습니다. 불러오기에는 **Contents → Read-only**, 업로드에는 **Read and write** 권한이 필요합니다.

검사와 다운로드가 완료돼야 현재 작업을 교체합니다. 불러오기에 성공한 토큰은 저장소별로 기기 키체인에 저장하며, 같은 저장소 주소를 입력하면 다시 불러옵니다. 업로드용 토큰과는 별도로 보관합니다. 자세한 사용법은 [JSON 불러오기 가이드](USER_GUIDE.md#기존-json-불러오기)를 참고하세요.

### 공개 저장소를 사용하는 경우

토큰을 발급하지 않고 사용하려면 다음 순서로 진행합니다.

1. 앱에서 **JSON 내보내기**으로 파일을 내보냅니다.
2. GitHub 웹사이트에 로그인하고 쓰기 권한이 있는 공개 저장소를 엽니다.
3. 원하는 브랜치·폴더에서 **Add file → Upload files**로 JSON을 올리고 커밋합니다.
4. 파일의 **Raw** 주소를 SideStore에 등록합니다. 공개 JSON을 읽는 사용자에게는 로그인이나 토큰이 필요하지 않습니다.

앱에서 **GitHub에 업로드하기**로 직접 파일을 생성·수정하려면 공개 저장소도 토큰이 필요합니다. 아래 토큰 발급 절차에서 대상 공개 저장소를 선택하고 **Contents → Read and write**를 부여하세요.

### 비공개 저장소를 사용하는 경우 — Fine-grained personal access token

1. GitHub의 **Settings → Developer settings → Personal access tokens → Fine-grained tokens**에서 토큰을 만듭니다.
2. **Resource owner**를 확인하고 **Repository access**에서 업로드할 비공개 저장소를 선택합니다.
3. **Repository permissions → Contents → Read and write**를 설정하고 토큰을 생성합니다.
4. 앱의 **파일 → GitHub에 업로드하기**에서 저장소·브랜치·JSON 경로와 토큰을 입력합니다.
5. **JSON 업로드하기**를 누르고 완료 후 **GitHub에서 보기**로 확인합니다. 기존 파일은 덮어쓰고 없는 파일은 새로 만듭니다.

비공개 저장소의 파일은 일반 공개 Raw 주소로 배포할 수 없습니다. SideStore에 배포하려면 JSON과 IPA/ADP가 대상 사용자에게 열리는 별도 배포 경로가 필요합니다. 앱의 업로드용 토큰은 SideStore에 자동 전달되지 않으며, JSON이나 공유할 URL에 넣으면 안 됩니다.

비공개 저장소도 GitHub 웹사이트에서 로그인 후 수동 업로드하면 별도 토큰 발급은 필요하지 않습니다. 다만 파일의 접근 제한은 유지됩니다.

자세한 절차와 비교표는 [사용 가이드](USER_GUIDE.md#11-github에-json-업로드하기)를 참고하세요.

## 빌드와 설치

- Xcode에서 `Source.xcodeproj`를 엽니다.
- 배포 대상: iOS 17 이상.
- 앱 식별자가 `app.sourceeditor`로 변경되어 기존 설치본과 별개 앱으로 설치됩니다. 기존 작업은 이전 앱에서 JSON으로 저장한 뒤 새 앱에서 가져오세요. 저장소별 GitHub 토큰도 새 앱에서 다시 입력해야 합니다.
- 제공된 IPA는 코드 서명 및 프로비저닝이 없는 빌드입니다. SideStore 등에서 기기용으로 서명해 설치하거나 Xcode에서 자신의 개발 팀을 선택해 다시 빌드하세요.
- 터미널에서는 `./scripts/build-ipa.sh`로 서명되지 않은 IPA를 `build/Source.ipa`에 만들 수 있습니다.
- GitHub의 **Actions → Build Source Editor IPA → Run workflow**를 수동 실행하면 빌드 결과에 `Source_Editor.ipa` 아티팩트와 **iPhone/iPad Safari download** 링크가 표시됩니다. iPhone/iPad에서는 결과 화면의 링크를 눌러 해당 저장소의 Release에서 IPA를 직접 받으세요. Actions의 아티팩트 미리보기 화면에서 파일을 저장하면 일부 환경에서 끝부분이 잘린 파일이 만들어질 수 있습니다.
- 수동 실행으로 만든 Release는 실행 번호마다 별도로 생성됩니다. 공개 저장소의 Release는 공개되며, 비공개 저장소의 Release는 접근 권한이 있는 사용자만 볼 수 있습니다. IPA는 서명되지 않았으므로 Feather로 서명한 뒤 설치해야 합니다. 파일의 생성일과 수정일은 다운로드하는 기기와 방식에 따라 다운로드 시각으로 표시될 수 있습니다.
- **Actions → Delete past runs and releases → Run workflow**를 수동 실행하면 완료된 워크플로 기록과 모든 Release, 각 Release에 연결된 태그를 삭제합니다. 실행 중인 정리 작업과 Release에 연결되지 않은 태그는 남습니다.
